## 软连接和硬连接
- 1.硬链接方面，硬链接通过 ln 源文件 目标文件 创建，多个文件名指向同一个 inode，与源文件完全平等，不存在"本体"与"快捷方式"的区别。删除其中一个文件名只是减少 inode 的链接计数，不影响数据本身，只有当所有硬链接都被删除后磁盘空间才真正释放。硬链接不能跨文件系统（inode 号仅在同一个分区内有效），也不能链接目录（防止目录树形成环路），适合用于重要数据的防误删备份。
- 2.软链接方面，软链接通过 ln -s 源文件 目标文件 创建，本身是一个独立文件，拥有自己的 inode，文件内容中存储的是目标文件的路径字符串，访问时系统自动解析并跳转到目标。软链接可以跨文件系统、可以链接目录，但源文件被删除或移动后软链接会失效变为悬空链接。常用于软件版本切换（如 python3 → python3.12）和多位置共享配置。可通过 ls -l 查看链接指向、ls -i 对比 inode 号、readlink -f 追踪完整解析链来区分两者，创建软链接时推荐使用绝对路径以避免移动后断链。

## 打包压缩和解压缩
- 1.gzip只做一件事情：压缩单个文件，无法打包目录，压缩 file.txt → 生成 file.txt.gz，原文件被删除。gunzip就是解压单个文件，file.txt.gz被删除
- 2.zip 同时做两件事：打包 + 压缩，一个命令搞定目录。zip -r archive.zip dir/，打包并压缩dir/目录，压缩文件名为archive.zip。unzip archive.zip是解压这个文件。unzip archive.zip -d /opt/，是解压到特定目录。使用zip会让原来的保留下来
- 3.tar(最经常使用)，tar -zcvf app.tar.gz opt/,打包 + gzip 压缩opt/这个目录（最常用）。tar -zxvf app.tar.gz -C /opt/, 就是把 app.tar.gz 解压到 /opt/ 目录下。tar 是"只生成新的，不动旧的"
- 4.-zcvf = 用 gzip 压缩并创建归档，显示过程，指定文件名。拆开就是：-z（gzip 算法）+ -c（创建）+ -v（显示过程）+ -f（指定文件名）。解压时把 -c 换成 -x，变成 -zxvf，意思就是“用 gzip 解压，显示过程，指定文件名”。

## mv的基本使用
- 1.mv = 移动 + 重命名，同一文件系统内是原子操作（瞬间完成、不占额外空间），跨文件系统才是“复制+删除”。
- 2.重命名（源和目标在同一目录），mv old.txt new.txt，mv old_dir/ new_dir/，文件和目录都可以，绝对路径mv /home/hadoop/a.txt /opt/a.txt
- 3.mv 的五个常用选项可总结为一套安全与效率并重的组合拳：-i 在覆盖前询问防止误覆盖，-f 强制覆盖不询问适合脚本批量操作，-n 不覆盖已存在文件以保留目标目录原有内容，-u 只覆盖更新的文件用于增量同步，-v 显示移动过程让你看清楚动了什么，而 -b 会在覆盖前自动备份原文件（加 ~ 后缀），防止覆盖后无法恢复。

## cp
- cp 命令用于复制文件或目录，基本用法包括：将文件复制到目标目录（cp file.txt /opt/）、复制的同时重命名（cp file.txt /opt/file_backup.txt）、递归复制整个目录（必须加 -r，如 cp -r mydir/ /opt/），以及一次性将多个文件复制到目标目录（cp a.txt b.txt c.txt /opt/），且原文件始终保持不变。

## crontab 定时任务
- 注意：CentOS / RHEL / Rocky里面的服务名叫crond，但是crontab的指令通用，crontab 的语法和用法全 Linux 通用，唯一不通用的是服务管理命令（cron vs crond）和日志路径，写文档或脚本时注意区分发行版就行。
- 1.crontab -e 只做一件事情：编辑当前用户的定时任务列表，写入的任务由 cron 守护进程在指定时间自动执行，原任务列表被覆盖。保存退出后无需重启服务，cron 会自动加载。
- 2.contab -l 同时做两件事：查看 + 确认当前用户的定时任务内容，一个命令搞定任务审计。配合 crontab -r 可以删除所有任务，但 -r 没有确认提示，极易误删，建议用 -l 先确认再操作。
- 3.时间格式（最核心），* * * * * command，分 时 日 月 周 + 命令，5 个星号各管一段。支持 */5（每5分钟）、1-5（周一到周五）、0 2 * * *（每天凌晨2点）等写法。crontab 里 % 有特殊含义，日期格式化必须写成 \%Y\%m\%d。
- 4.任务执行三要素 = 绝对路径 + 输出重定向 + 环境变量。拆开就是：命令和脚本用绝对路径（如 /usr/bin/python）+ 输出重定向到日志文件（>> /tmp/cron.log 2>&1，避免邮件骚扰）+ 手动声明 PATH（cron 环境极简，不继承用户 shell 的环境变量）。
- 5.特殊字符串（快捷写法），@reboot command 开机执行一次，@daily command 每天凌晨执行，@hourly command 每小时执行。比手写五个星号更直观，适合简单周期场景。
- 6.排错流程，任务没执行 → systemctl status cron 确认服务运行 → 查 /var/log/syslog | grep CRON 看执行记录 → 手动用绝对路径跑一遍命令确认可用 → 检查输出日志定位错误。
- 7.可以使用systemctl restart cron来重启cron服务

## 软件包的查询卸载和安装
- 查询方面，Ubuntu 使用 dpkg -l 列出所有已装软件，dpkg -l | grep 名称 定位具体包，dpkg -S 文件路径 反查文件归属，dpkg -L 包名 查看包安装了哪些文件，apt show 软件名 查看软件的版本、详情及依赖信息；CentOS/RHEL 对应使用 rpm -qa、rpm -qa | grep 名称、rpm -qf 文件路径、rpm -ql 包名，以及 rpm -qi 软件名 查看已装软件的版本、发布信息和详细描述。两类系统底层工具（dpkg/rpm）只负责查询本机数据库，不联网也不处理依赖。

- 安装、卸载与升级方面，日常操作应优先使用高级包管理器：apt install / apt remove / apt purge（Ubuntu），dnf install / dnf remove / dnf upgrade（CentOS/RHEL），它们自动解析并处理好依赖关系。底层安装工具 dpkg -i xxx.deb 和 rpm -ivh xxx.rpm 仅用于安装本地包文件，不会自动解决依赖，装完通常还需补一句 apt -f install 修复。底层卸载工具 rpm -e 软件名 可直接删除指定包（--nodeps 可强制跳过依赖检查，--test 可模拟卸载），对应 Ubuntu 侧日常用 apt remove 即可，dpkg 无直接等价的单条卸载命令；卸载时 Ubuntu 的 remove 保留配置文件而 purge 彻底清除，CentOS 的 remove 直接连配置一起删除。升级流程统一为先更新索引（apt update / dnf check-update）再执行升级（apt upgrade / dnf upgrade）。

- apt list 查询方面，直接运行 apt list 会列出软件仓库中所有可用的包（未装也显示），输出格式为"包名/发行版版本 版本号 架构"，默认无状态标记；加上 --installed 参数后仅列出已安装的包，且已装包末尾会带 * 号。常用组合包括 apt list | grep 关键词 搜索仓库、apt list --installed 查看已装、apt list --upgradable 查看可升级项。注意 apt list --installed 不能与其他选项混用，否则报错。对应 CentOS/RHEL 侧为 yum list / dnf list 及子命令 installed、upgrades。
区分"仓库里有"和"本机已装"的关键是用 apt list --installed （标记为 [installed,automatic]）或 dpkg -l 确认，而非直接 apt list | grep——后者会把未安装的仓库包一并列出，造成"装了好多"的错觉。

## shell里面的特殊变量
- 1.在 Linux Shell 脚本中，系统预定义了一些特殊变量，用于获取脚本运行时的参数、状态和进程信息。
- 2.$0​ 表示当前脚本的文件名。执行脚本时传入的第一个参数用 $1​ 表示，第二个用 $2，以此类推。当参数位置超过第 9 个时，必须用花括号包裹，如 ${10}。
- 3.$#​ 表示执行脚本时传入的参数总个数，常用于在脚本开头校验参数是否足够。
- 4.$*​ 和 $@​ 都代表所有参数，但行为有本质区别：当用双引号包裹时，"$*" 会把所有参数合并成一个字符串，而 "$@" 会保持每个参数独立（包括带空格的参数不会被拆散）。实际编程中几乎总是用 "$@"，只有需要把所有参数当一整段文本处理时才用 "$*"。
- 5.$?​ 表示上一条命令的退出状态码。返回值为 0​ 代表执行成功，非 0 代表执行失败。这是脚本中做条件判断（如检查某个命令是否执行成功）最常用的变量。
- 6.$$​ 表示当前 Shell 进程的 PID（进程号），常用于生成唯一的临时文件名。
- 7.$!​ 表示后台运行的最后一个进程的 PID。
- 8.$_​ 表示上一个命令的最后一个参数。
- 9.这些特殊变量不是拿来单独敲的，要用 echo 打印

## shell运算符
- 1.整数运算使用 $[] 语法，例如 a=10; b=3; echo $[a+b] 输出 13，echo $[a/b] 输出 3（整数除法截断小数），echo $[a**2] 输出 100。变量直接参与运算无需额外符号，如 echo $[a+b*c]。
- 2.浮点运算必须通过 bc 命令，例如 echo "scale=2; 10/3" | bc 输出 3.33，scale 控制小数位数。变量可嵌入表达式：a=3.5; b=2.1; echo "$a + $b" | bc 输出 5.6。
- 3.整数比较在 [] 中使用特定的运算符，共六个，对应关系如下：-eq（equal，等于）、-ne（not equal，不等于）、-gt（greater than，大于）、-ge（greater than or equal，大于等于）、-lt（less than，小于）、-le（less than or equal，小于等于）。单中括号 [ 后和内容之间必须有空格，变量参与运算需加 $ 前缀。需要在下面使用echo $?,看结果，如果是0则正确，1则错误。
- 4.常用包括 -e（文件是否存在）、-f（是否为普通文件）、-d（是否为目录）、-r（是否可读）、-w（是否可写）、-x（是否可执行）、-s（文件大小是否大于 0）。如：[ -e 1.text ],然后在下面使用echo $?,看结果，如果是0则存在，1则不存在。

## shell中if的条件判断
- 1.if 语句用于根据条件是否成立来决定执行哪段代码，基本结构由 if、then、elif、else、fi 五个关键字构成，fi 是 if 的倒写，标志语句块结束。
- 2.基本语法有三种形式。单分支：if [ 条件 ]; then 命令; fi。双分支：if [ 条件 ]; then 命令1; else 命令2; fi。多分支：if [ 条件1 ]; then 命令1; elif [ 条件2 ]; then 命令2; else 命令3; fi。关键字之间必须用空格分隔，if[[ 和 elif[[ 均为错误写法，正确形式为 if [[ 和 elif [[。
- 3.条件写法有三种。[ ]（单中括号）基于 test 命令，内部需空格，整数比较用 -eq、-ne、-gt、-ge、-lt、-le，字符串比较用 = 和 !=，文件测试用 -e、-f、-d 等，多条件用 -a（与）、-o（或）、!（非）。[[ ]]（双中括号）为 Bash 扩展，支持直接用 &&、|| 连接条件，支持 <、> 符号，支持 == 模式匹配和 =~ 正则匹配，变量可不加引号，功能更强。test 命令与单中括号完全等价，如 test $a -eq 10 等同于 [ $a -eq 10 ]。
- 4.常见条件类型包括整数比较、字符串判断（用 -z 判空、-n 判非空）、文件测试（存在性、类型、权限）、命令执行结果判断（直接写命令，$? 为 0 则条件成立）。多条件组合在 [] 中用 -a/-o/!，在 [[]] 中用 &&/||/!。
